# UART v3: атомарная настройка DDS и перестраиваемые фазомеры

**Русский** · [English](protocol-v3.en.md)

Актуальная реализация на 03.11.2026. Приложение 0.5.1 и CLI
`app/tools/fpga_config.py` поддерживают v3. Проверенный образ и новая
контрольная сборка описаны в [разделе FPGA](../fpga/README.md).

## Такты, назначения и ограничения

- AD9959 SYSCLK номинально 500 МГц; SYNC_CLK 125 МГц; АЦП 250 квыб/с.
- CH0/CH2 — НЧ-пара, CH1/CH3 — ВЧ-пара; выходы не переставляются.
- Положительные разности FTW: `delta_low=CH2−CH0`, `delta_high=CH1−CH3`.
  Перестановка стороны гетеродина не поддерживается этой версией.
- Каждая разность допускается **8590…171799**, то есть примерно 1…20 кГц.
  Реальные границы: 1000,007614…20000,035398 Гц. Отклонение верхней границы
  от 20 кГц — округление к ближайшему шагу DDS, а не дополнительная полоса.
- FTW каждого выхода: 1…`7FFFFFFF`; это цифровое ограничение первой зоны
  Найквиста, не подтверждение полосы, линейности или допустимой мощности платы.
- POW: 0…16383, `phase_deg=POW*360/16384`. ASF: 0…1023, без перевода в мощность.
- Аналоговые и цифровые фазовые пары: канал 3−1 (X11−X9, ВЧ) и канал 4−2
  (X12−X10, НЧ). Разные ПЧ между собой не сравниваются.

Стартовые значения обновлены 2026-11-03 по выбранному стендовому профилю:

| Выход | FTW | POW | ASF |
|---|---:|---:|---:|
| CH0 | 12845056 | 0 | 200 |
| CH1 | 635888254 | 0 | 1000 |
| CH2 | 12879416 | 0 | 1000 |
| CH3 | 635830272 | 0 | 450 |

Стартовые ПЧ: НЧ **4000,030458 Гц**, ВЧ **6749,993190 Гц**.
Начальные шаги NCO и ожидаемые цифровые периоды выведены из того же банка;
при сбросе настройки DDS и фазомеры не расходятся.

Настройки временные: после сброса используются стартовые значения. FPGA не
записывает параметры в EPCS4. Сохранение желаемого профиля на ПК — задача приложения.

## Запрос, 12 байт

Все многобайтные значения little-endian. Линия 115200, 8N1, TTL 3,3 В, X5.

| Смещение | Размер | Содержание |
|---|---:|---|
| 0 | 2 | `A5 5A` |
| 2 | 1 | Версия `03` |
| 3 | 1 | Длина `0C` |
| 4 | 1 | `01 SET_PARAMETER` / `02 GET` |
| 5 | 1 | Идентификатор параметра / вид GET |
| 6 | 2 | ID запроса |
| 8 | 2 | Значение |
| 10 | 2 | CRC16 байтов 2…9 |

CRC-16/MODBUS: начальное `FFFF`, отражённый полином `A001`, без финального XOR;
CRC младшим байтом вперёд. ASCII `123456789` → `4B37`. Неверная CRC, версия
или длина не исполняется; ответа нет. Межбайтовый тайм-аут незавершённого
запроса 30 мс. Сохраняется одна ожидающая команда во время передачи ответа.
Рекомендуется только один незавершённый запрос на стороне ПК.

Самопроизвольной телеметрии нет. FPGA v3 не принимает запросы v2. Декодер
`fpga_measurements.py` умеет читать обе версии, но по умолчанию отправляет v2,
чтобы сохранить работу с ещё не обновлённой платой. CLI `fpga_config.py`
явно использует v3.

## SET: подготовка полного банка и применение

| ID | Значение | Действие |
|---|---:|---|
| `F0` | `B001` | BEGIN: очистить маску полученных слов, начать новую транзакцию |
| `10`…`1F` | 16-битное слово | Записать слово во временный банк M9K |
| `F1` | `A55A` | COMMIT: проверить весь банк и применить одновременно |
| `F2` | 0 | ABORT: забыть подготовленный банк, действующий не менять |

Для канала `c=0…3` его слова расположены по ID `10h+4*c`:

| Прибавка к ID | Значение |
|---|---|
| 0 | FTW[15:0] |
| 1 | FTW[31:16] |
| 2 | POW, старшие два бита должны быть нулевыми |
| 3 | ASF, старшие шесть бит должны быть нулевыми |

После BEGIN обязательны **все 16 слов**. Порядок слов произвольный, повтор
слова заменяет его подготовленное значение. BEGIN отменяет предыдущую
незавершённую транзакцию. Проверка диапазонов производится при COMMIT.
Неуспешная проверка не меняет действующие параметры и не вызывает IO_UPDATE.
После ошибки диапазона можно исправить слова и снова выполнить COMMIT.
После успешного COMMIT для следующего изменения нужен новый BEGIN.

Обычный цикл ПК: BEGIN → 16 слов с проверкой каждого ACK → COMMIT → GET конфигурации.
ACK `STAGED` означает только приём во временный банк. ACK `OK` на COMMIT
выдаётся после фактической последовательности записи DDS, общего обновления
и выдержки установления. Чтение конфигурации возвращает применённые FPGA
настройки; это **не электрическое чтение регистров AD9959 по SPI**.

Если ACK COMMIT потерян, нельзя автоматически повторять всю операцию:
сначала прочитать банк и поколение, выяснить, применилось ли изменение.

## Короткий ответ, 12 байт

`A5 5A 03 0C`, затем:

| Смещение | Поле |
|---|---|
| 4 | `81` SET, `82` ошибочный GET, `FF` неизвестная команда |
| 5 | Статус |
| 6 | ID параметра из запроса |
| 7 | 0 |
| 8…9 | ID запроса |
| 10…11 | CRC16 байтов 2…9 |

Статусы: 0 `OK`, 1 `NOT_IMPLEMENTED` (резерв прежних ID 0…15),
2 `UNKNOWN_COMMAND`, 3 `BAD_ARGUMENT`, 4 `STAGED`, 5 `BUSY`, 6 `INCOMPLETE`.

## GET конфигурации: параметр 1, значение 0

Ответ 48 байт:

| Смещение | Размер | Поле |
|---|---:|---|
| 0…3 | 4 | `A5 5A 03 30` |
| 4…5 | 2 | `82 00` |
| 6 | 1 | `80`: признак ответа конфигурации |
| 7 | 1 | bit0: инициализация/применение ещё не завершены |
| 8 | 2 | ID запроса |
| 10 | 2 | Поколение настроек; 0 после запуска, +1 на успешный COMMIT, modulo 65536 |
| 12 | 32 | Четыре записи CH0…CH3: FTW uint32, POW uint16, ASF uint16 |
| 44 | 2 | Резерв, 0 |
| 46 | 2 | CRC16 байтов 2…45 |

## GET измерений: параметр 0, значение 0

Ответ **112 байт**. Байты 4…87 сохраняют расположение полей v2:
статус, valid/ошибки, ID, АЦП, счётчики, восемь фаз, четыре модуля I/Q,
сырые АЦП1…8, цифровой счётчик и порог амплитуды.
Сигнатура теперь `A5 5A 03 70`. Полная таблица первых полей находится в
[протоколе v2](protocol-v2-fields.md); CRC v2 на 94…95 в v3 отсутствует.

| Смещение | Размер | Поле v3 |
|---|---:|---|
| 88 | 4 | Период ВЧ, uint32, такты 125 МГц |
| 92 | 4 | Период НЧ, uint32, такты 125 МГц |
| 96 | 1 | Возраст цифрового результата, мс, насыщение 255 |
| 97 | 1 | Диагностика: RX / очередь / цифровое переполнение, bits 0/1/2 |
| 98 | 2 | Поколение настроек |
| 100 | 4 | delta_high FTW |
| 104 | 4 | delta_low FTW |
| 108 | 1 | bit0: перестройка/инициализация, результаты непригодны |
| 109 | 1 | Резерв, 0 |
| 110 | 2 | CRC16 байтов 2…109 |

Фазы signed32: `deg=value*360/2^32`, интервал [−180,180).
Цифровые фазы сохраняют 24 значащих бита. Перевод модуля в пиковые отсчёты
АЦП остаётся `2*magnitude/(1000*1.646760258121)`; один отсчёт 0,000375 В.
ADC5…8 передают сырые напряжения детекторов, без калибровки мощности.
Порог пригодности этих входов: **|U| ≥ 0,5 В на каждом АЦП5…8**;
отрицательная полярность разрешена по уточнению владельца.
Для offset-binary и 375 мкВ/отсчёт проходят коды `≤31434` или `≥34102`.
Ближайшие уровни: ±0,499875 В не проходят, ±0,500250 В проходят.
Модуль здесь относится к напряжению детектора относительно 0 В, а не к
амплитуде синусоид АЦП1…4. Поле `min_amplitude_counts` на байтах 86–87
остаётся **100** и по-прежнему описывает порог I/Q-амплитуды АЦП1…4.
Формат пакета и версия протокола не изменены.

## Синхронность, окна и пригодность

FIR исключён из проекта. Аналоговый фазомер использует непосредственно АЦП1…4:
два точных NCO, окно 1000 отсчётов / 4 мс, выдача каждые 250 отсчётов / 1 мс.
Выполняется трёхпараметрический МНК по cos, −sin и постоянной составляющей;
это учитывает неполное число периодов и не требует FFT или поиска частоты.
Чистое изменение масштаба синусоиды не меняет фазу в идеальной модели.
Квантование, шум, гармоники, насыщение и изменение амплитуды внутри окна
остаются источниками ошибки. Валидность требует достаточной амплитуды,
заполненного окна, отсутствия ошибок/клиппинга и достаточной энергии нужного тона.

Цифровой фазомер использует два NCO на 125 МГц, 18-битные интервальные
счётчики, 16 фронтов каждой полярности. Допуск периода: примерно ±3,125% и
4 такта. Нет фронтов более 1,5 ожидаемого периода — снятие пригодности;
проверка четырёх каналов занимает до 128 нс дополнительно. Возраст последнего
цифрового результата должен быть **менее 20 мс**. Это нужно для окна 16 мс
при ПЧ 1 кГц. Повтор цифрового счётчика в соседних запросах 100 Гц допустим,
если аналоговый результат свежий и цифровые valid/возраст пригодны.

При неисправности любого цифрового входа снимаются оба цифровых valid.
После восстановления нужны новые фронты. Окна АЦП и компараторов имеют
разные длительности/середины; одинаковое время движения ими не гарантируется.
Задержанный beam_lost 100 мс сохранён; контроллеру не нужно ждать его,
чтобы снять пригодность по valid или тайм-ауту связи.

Если хотя бы один из детекторов АЦП5…8 ниже порога по модулю, снимаются
оба аналоговых и оба цифровых флага пригодности. Проверка использует отсчёты
того же завершённого блока, которые передаются в пакете; результат обновляется
с шагом 1 мс. Нет дополнительного ожидания 100 мс для снятия valid. После
возвращения всех уровней и остальных условий пригодность восстанавливается
автоматически; beam_lost также сбрасывается. Исходные напряжения детекторов
передаются и при недостоверности. Поле channel_valid остаётся диагностикой
синусоидальных каналов АЦП1…4, поэтому само по себе не означает общий valid.

При COMMIT фазовые накопления сбрасываются, выдача достоверности запрещена.
UART и АЦП не переинициализируются. Банк AD9959 записывается single-bit SPI,
после всех 20 кадров формируется **один IO_UPDATE длительностью 32 нс**.
CFR=`000321`: single tone, matched pipeline, прежний режим DAC; автоматический
и постоянный сброс фазовых накопителей DDS выключены. POW — добавка к текущей
фазе накопителя, а не команда обнуления его истории. В отсутствие COMMIT
повторных записей и обновлений нет.

Для IO_UPDATE используется второй выход того же PLL: 125 МГц с фазой −1,25 нс
относительно входного SYNC_CLK. TimeQuest проверяет setup и hold относительно
следующего выбранного фронта DDS, включая tSU=4,8 нс и **предварительный суммарный
бюджет дорожек SYNC_CLK+IO_UPDATE 0,5 нс**. Этот бюджет ещё не измерен на плате.
После ACK DDS выдерживается 2 мс, затем заполняются новые измерительные окна.
2 мс — реализованная выдержка, не стендовая проверка всех переходных процессов.

## Работа с ПК и скорость

```powershell
# Только сформировать пример JSON; порт не открывается.
.\.venv\Scripts\python.exe tools/fpga_config.py --defaults-json
# Команды из каталога app; замените COM3 своим портом:
.\.venv\Scripts\python.exe tools/fpga_config.py --port COM3 --read-config
.\.venv\Scripts\python.exe tools/fpga_config.py --port COM3 --request
.\.venv\Scripts\python.exe tools/fpga_config.py --port COM3 --set-config desired.json
# Циклическое чтение с сохранением исходных UART-байтов и таблицы:
.\.venv\Scripts\python.exe tools/fpga_measurements.py --port COM3 --protocol-version 3 --seconds 30 --csv captures/run-v3.csv --raw captures/run-v3.bin
```

112 байт ответа + 12 байт запроса при 115200 8N1 требуют минимум 10,764 мс,
до ожидания результата и задержек USB/ОС. Поэтому 100 полных ответов/с на этой
скорости не достигаются; жёсткий теоретический предел меньше 93/с.
GUI и калибровка реализованы в приложении ПК. Расчёта расстояния/скорости в FPGA пока нет. Старую калибровку нельзя автоматически применять
к другим частотам и режимам аналогового тракта.


## Поддержка настольным приложением

Приложение 0.5.1 отправляет v3 и поддерживает полный банк DDS с единым
COMMIT и проверкой readback. Стартовый профиль приложения и FPGA совпадает:
ПЧ НЧ 4000,030458 Гц, ВЧ 6749,993190 Гц. Настройки сохраняются на ПК,
а в плату отправляются по кнопке. [Инструкция приложения](../app/README.md).
